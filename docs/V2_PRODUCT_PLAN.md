# V2 产品优化计划（设计稿，待审核）

## 目标与边界

V2 的目标是让儿童**愿意和团团继续探索**：认识会回应当前旅程的团团，理解英语任务为什么出现在故事中，看见星星与共同发现的联系。设计基于 [Alpha 反馈主题分析](ALPHA_FEEDBACK_ANALYSIS.md)；目前缺少已填写的真实试玩记录，所有优先级均待观察验证。

本文件是产品方案，不授权本轮写代码或制作新玩法。保留现有 `home → story → games → reward → pets` 路径与 `pets/`、`story/`、`games/`、`reward/`、`game/`、`curriculum/` 模块；第一章与当前本地档案继续有效。不改变团团的陪伴伙伴定位，不把米米或团团变成评分工具。

## 体验原则

1. **角色因事回应**：团团只根据已发生的剧情与互动回应，不猜测孩子的心情、能力或家庭情况。短句、可跳过、可重复听，不制造照料压力。
2. **英语推动发现**：每个词或句型有明确的故事用途；完成后角色给出可理解的因果反馈。正确与错误反馈都提供继续探索的路径。
3. **奖励有来源和去向**：星星对应明确的探索里程碑，可回看、无随机性、无付费或限时压力，重复游玩不刷星。
4. **内容与状态分离**：教材 PDF 候选内容经过版权确认和人工审核；多年级及家长端沿用稳定 ID、内容版本和学习记录摘要，不让页面直接修改个人进度。

## 关键交互草案

### 团团打招呼

首页团团有可辨识的“可互动”提示。孩子轻触后，团团做简短表情或动作，给出与当前进度相符的一句话，并提供一个清楚的下一步入口。多次轻触可以切换少量同义表达，但不会发放星星、扣减任何状态，也不会要求孩子每天回来。离开再返回时优先显示最近的冒险事实；没有记录时使用通用欢迎语。

### 第一章冒险任务

保留三轮听音找图与原判定规则。任务开始前讲清“我们要用声音找到图卡线索”；每轮选择之后连接英文词、图片与现场线索；三轮结束用一个简短结论引向第四幕。答案与英文学习目标必须正确，线索推理不能只靠误导性图片。先让儿童复述“我们为什么听这些词”，若讲不出来就修改内容表述，而非增加更多按钮。

### 星星用途

第一步让孩子看见每笔星星的来源和累计结果。第二步只做纸面／低保真原型：例如星星达到明确数量时点亮树屋的一处纪念装饰，孩子可预览结果且不会失去星星。与现有家具奖励类型保持兼容；是否真正实现装饰解锁，应先看儿童是否理解并在结尾主动提到它。家长端将来只展示获得记录与学习摘要，不提供改写星星的入口。

## 分阶段决策与验收

| 阶段 | 产物与决策 | 验收依据 |
| --- | --- | --- |
| A. 反馈补证 | 收集真实试玩模板，归纳重复卡点，标记设备问题与理解问题 | 每项结论能追溯到测试者代号、环节、行为或原话；样本不足时保留“不确定” |
| B. 文字与流程原型 | 团团情境对白表、第一章线索因果图、星星纪念物草图 | 角色语气符合 `GAME_DESIGN.md`；孩子无需解释即可指出下一步；教材词与故事逻辑可人工核对 |
| C. 小范围复测 | 用原型或后续获批实现，对目标年龄儿童复测 | 记录主动互动、任务复述、奖励理解和继续意愿；比较卡点是否减少，不以刷点击或答对率代替兴趣 |
| D. 实施审核 | 根据复测结果确定独立开发 Sprint 与文件范围 | 每个功能有清晰来源 ID、状态边界、存档兼容方案、素材授权及家长端摘要影响 |

优先解决阻断性问题：无法进入下一步、音频无退路、奖励或存档异常。其次解决“知道怎么点，但不知道为什么点”的体验问题。低优先级的动画数量、装饰数量与对白数量不应先于上述验证扩大。

## 架构与内容约束

- `story-manager` 继续拥有剧情游标与任务触发；小游戏模块继续拥有题目判断与回合恢复；`reward-manager` 继续按奖励 ID 幂等发放。页面只呈现状态并提交操作，不直接写存档。
- 团团对白仍放在角色内容层；情境选择只读取必要的章节、任务与伙伴状态。新状态字段如确有必要，应先说明旧档案迁移与失败回退，不能覆盖 Alpha 进度。
- 星星的“累计获得”和未来可能的“使用”在概念上分开；本计划采用不消耗的里程碑原型，暂不新增余额或价格规则。
- 正式教材内容进入剧情和小游戏前，保留教材、年级、册别、单元、知识点、来源位置及审核状态；不得直接复制未授权 PDF 图文或使用来源不明的角色素材。
- 对家长端只规划可解释的学习与冒险摘要，不展示孩子的负面能力标签，不用答错次数惩罚伙伴关系。
