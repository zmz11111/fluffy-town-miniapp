# 教材 PDF 接入计划（Sprint 5-A）

> 设计稿，待审核。目标是把经授权、人工校对的教材材料整理成可维护的 Unit 知识库，并供学习任务和游戏内容引用。PDF 不作为客户端的运行时数据库。本文件不代表当前导入内容已获发布批准。

## 1. 范围与现有资料边界

现有解析工作目录含外研版三年级上册学生用书、教师用书和单词表的 Unit 1 候选数据。目录位置记录为：Welcome → Unit 1～Unit 6 → Appendices。用户已确认：**单词表覆盖 Welcome 和 Unit 1～Unit 6，不包含 Appendices 的单词**。因此：

- Appendices 可作为学生用书结构或参考资料保留；没有单词表支持时，不从 Appendices 新建教材词表。
- Welcome 词条属于前置范围，不并入 Unit 1 的单元词汇；例如 `hello`、`hi`、`name` 可在 Unit 1 课文再次出现，但须通过先修词引用，而非重新归属。
- 学生用书用于确认章节／情境、句型和页面位置；单词表是词条拼写及词表归属的主要来源；教师用书辅助梳理教学目标和组织建议。
- 教师用书中的建议不自动成为儿童任务；需转成适龄、原创、可验收的活动设计。
- 当前 Unit 1 的 `unit-info.json`、`vocabulary.json`、`sentences.json`、`learning-objectives.json` 均标记 `pending_human_review`／`not_for_runtime`。设计稿不把候选数据当成正式教材库。

**出版方、版本、使用权和授权范围尚须负责人核实**。资料来源文件只供获授权的内部整理与审校；未经确认，不把原书页图、长段课文、教师用书内容或扫描素材复制到游戏发布包。

## 2. 内容转换流程

```text
学生教材 PDF + 教师用书 PDF + 单词表 PDF
                 ↓ 来源登记、使用权确认、文件版本记录
         原件定位与候选抽取
                 ↓ 页码／印刷页／栏目／行列位置保留
       Unit 知识库（结构、目标、词汇、句型）
                 ↓ 人工核对英语、中文、范围、年级和审核状态
          教学目标与知识点映射
                 ↓ 审核内容用途、学习任务和完成证据
             学习任务定义
                 ↓ 原创场景、获授权音画、题目规则审查
               游戏内容
                 ↓ 发布校验与版本登记
          小程序静态内容包／后续内容仓库
```

上游一处修订时，利用稳定 ID 和 `sourcePointer` 查找下游引用；不得通过英文单词字符串全局替换教材内容或儿童历史记录。

## 3. 阶段 A：来源登记与范围锁定

每份输入先建文档清单，至少记录：

- `documentId`（例如 `student-book`、`teacher-book`、`word-list`）、文件名、版本／版权页信息、文件校验值和取得日期。
- 使用权状态、允许的内部处理用途、可否生成衍生内容、可否在小程序展示／分发；负责人和凭据位置。
- PDF 页码与书内印刷页码的对应关系；目录中的 Welcome、Unit 1～6、Appendices 边界。
- 抽取方法、人工复核人、日期、未解决的疑问。

若权利状态不清楚，将其标为禁止发布；只能在确认获准的范围内继续审校，不假定用户持有文件即等于取得小程序发布权。来源文件在项目镜像 `sources/` 中是只读材料，不复制、改名或移动这些同步文件。

## 4. 阶段 B：建立 Unit 知识库

### Unit 元信息

每个 Unit 作为独立版本化包，记录：

| 字段 | 设计含义 |
| --- | --- |
| `textbookId`、版本／版次 | 区分教材系列、版本、年级和册别；待版权页核对后确定。 |
| `grade`、`volume`、`unitId`、顺序 | 确认年级、上下册、单元稳定 ID 与目录顺序。 |
| `topic`、主题意义 | 用经过审校的简要描述，避免拷贝长篇教材说明。 |
| `sourceDocuments`、`sourcePointers` | 连接学生教材、教师用书和单词表中的页码、栏目、行列。 |
| `learningObjectives` | 对教学目标作准确、短小的结构化整理，保留引用位置并人工审阅。 |
| `prerequisiteKnowledgePointIds` | 单独引用 Welcome 或前序 Unit 知识，不重写归属。 |
| `rightsStatus`、`reviewStatus`、`contentVersion` | 控制候选、待审核、已批准和可发布状态。 |

### 单词与句型

- 单词词条用“教材版本 + 来源单元 + 词条／义项”生成稳定 ID。保留教材显示词形、中文义项、词类（如经审核）、难度（未确定时置空）、词表范围、来源页及位置。
- 同形多义词分别记录义项 ID；缩写或变形保留印刷形式与标准化形式，不静默修正扫描／印刷内容。
- 句型记录简短结构、适用功能、年级难度、知识点关联和学生用书来源位置。示例只保留策划与教学任务所必需的短语；游戏中的情境对白优先原创。
- 音频、图片、插图和字体是独立资源，不因存在于 PDF 就自动获得可发布授权。需单独标记文件来源、许可和适用范围。
- 教师用书可支持教学目标分析，但不将其整页说明或教学脚本复制成角色对白。

### 来源位置要求

每条抽取或转录内容至少可追到：

```text
documentId + pdfPage + printedPage（若有）+ locator
```

`locator` 说明内容处于目录、栏目、表格行／列、页眉或教师目标第几项。PDF 页码和书内页码不可混用。OCR／视觉提取内容必须带 `extractionType` 和复核状态；人工改字保留修订记录及依据。

## 5. 阶段 C：审校与学习任务定义

按以下顺序逐 Unit 审核：

1. **范围审校**：核对教材身份、单元顺序、Welcome／Unit／Appendices 归属；只词表有覆盖的 Welcome 与 Unit 1～6 词条进入词汇清单。
2. **内容审校**：逐条比对英文、中文、大小写、缩写、义项、标点、页码和栏目；不确定项保留备注，不猜测补全。
3. **教学审校**：将教师目标整理成孩子可观察的行为证据，例如在情境里识别合适问候；区分知识点、活动和评价建议。
4. **年龄审校**：确认任务用语、阅读量、听觉信息、先备知识和操作方式适合三年级初学者；难度缺乏官方依据时不伪造分级。
5. **版权审校**：确认内容是否能用于发布。词条短、常见不代表整组教材选编、插画、音频、对话或教师材料自动可复制。
6. **任务设计**：给每个任务列学习目标、引用知识点 ID、孩子提示、操作、完成证据、错误退路、是否复习和拟用游戏类型。

任务难度标记描述的是内容设计，不是儿童能力分。未通过来源、教学、英语和权利审查的项目保持 `pending_human_review`，不得引用为运行时儿童内容。

## 6. 阶段 D：从学习任务到游戏内容

游戏内容包引用已审核的任务和知识点，不从 PDF 页面现场取题：

| 知识／任务 | 可选的呈现候选 | 发布前需确认 |
| --- | --- | --- |
| 单词辨认 | 听音选词、词图匹配、原创情境选义 | 录音／图片授权、答案唯一、义项正确；无图片资源时不强制配图。 |
| 句型理解 | 角色对话选择、短语排序、情境回应 | 原创对白、语序与标点正确、选项适龄且无歧义。 |
| 听力理解 | 播放短音频后选线索或文字 | 音频可重播、可访问替代存在、内容与词条完全一致。 |
| 口语尝试 | 跟读／自主表达的非录音提示 | 自愿、可跳过；MVP 不做语音采集与准确率评分。 |
| 复习 | 用不同情境再次遇到已学 ID | 同义内容仍关联原知识点版本；旧教材进度映射经过确认。 |

每个题包／关卡还应声明：任务 ID、适用教材内容版本、年级、知识点引用、游戏类型、题目顺序、答案与干扰项、提示与重试、完成事件和奖励引用。答案只由游戏规则层判定，不暴露给页面；游戏不能自行扩充教材内容或任意发奖。

### 游戏化连接

```text
知识点 → 学习目标 → 冒险任务意图 → 原创剧情／角色回应
       → 经审核题包 → 游戏完成证据 → 已登记奖励（如适用）
```

剧情可以解释为什么要练习，但不得改写教材事实。奖励依据任务完成证据，而不是孤立答对一个词；同一目标和内容版本的奖励按稳定 ID 去重。当前 `curriculum/game-mapping/` 文件仍是 disabled／proposal，只有完成发布审核后才能启用。

## 7. 版本、扩展与存档兼容

- 教材、单元、词条义项、句型、任务、题包均使用稳定 ID 与内容版本；相同拼写在不同教材、年级、册别或义项下不自动合并。
- 更新内容时保留原版本解释历史学习记录；若词条合并、拆分、改义项或跨 Welcome／Unit 归属，要提供明确映射方案并经人工批准。
- 新增教材或年级使用同一 schema 和校验器，但分别维护来源、版权和审核状态。不能以“共用结构”为由共享不相同的教学结论。
- 游戏答题与教材候选分开发布；内容包版本变更不能清空 `currentGame`、章节游标、学习记录或已领奖励。
- 当前 v4 本地档案不要求在 Sprint 5-A 改动。未来若需要增加记录字段，单独设计迁移、旧版字段兼容和升级失败恢复，再按独立 Sprint 实现。

## 8. 建议交付顺序与发布门槛

| 步骤 | 交付 | 通过条件 |
| --- | --- | --- |
| 1. 资料登记 | 文档清单、版次和位置对照表、授权待办 | 来源可辨识；内部处理和产品发布权利状态清楚。 |
| 2. Unit 结构整理 | 单元信息、Welcome 前置引用、词汇、句型与目标候选 | 每项有来源位置；不把 Appendices 当成单词表来源。 |
| 3. 人工审校 | 英语与中文校对、教学目标核对、难度与歧义标注 | 审核人、时间和问题记录完整；待查项未混入已批准包。 |
| 4. 学习任务定义 | 可观察目标、孩子提示、交互、错误退路、完成证据 | 目标儿童可以理解，内容和目标关系明确。 |
| 5. 游戏内容审核 | 题包、素材授权表、奖励引用、无障碍替代 | 答案唯一；资源有权使用；题目离线可用；奖励去重。 |
| 6. 版本发布评审 | 内容清单、版本号、回滚方案、学习记录映射 | 只发布已审核包；不破坏旧进度；负责人签核。 |

## 本阶段边界与待确认

- 本文件只设计教材到学习任务和游戏内容的路径，不解析新 PDF、不修改 `curriculum/` 文件、不接入 Alpha 游戏。
- Unit 1 现有候选资料仍需人工复核；具体出版信息、授权发布范围与难度尚未确认。
- 首期最终教材和单元需要产品负责人选定；未确认前继续使用原创示例完成交互设计评审。
- PDF 可内部处理不等于可以在小程序再发布其课文、图片、音频或教师资料；发布权利须逐项核实。
