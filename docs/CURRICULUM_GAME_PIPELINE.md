# 教材知识点到游戏内容的映射流程（Sprint 3.5-B）

本阶段建立 **Unit 1 待审校教材内容 → 游戏内容候选** 的静态映射。文件位于 `miniprogram/curriculum/game-mapping/`，不会被当前小程序加载；既有剧情、小游戏、奖励和伙伴模块未改动，也没有正式剧情。

## 流程

```text
学生教材 / 教师用书 / Welcome–Unit 6 单词表
        ↓ 标记 PDF 页、书内页和词表行列；人工审校
imports/unit1：单元、词汇、句型、教学目标
        ↓ 稳定 ID 引用，按语义选择玩法与任务意图
game-mapping：单词 → 游戏候选；句型 → 对白/互动/口语用途；
              教学目标 → 任务/伙伴互动/冒险目标
        ↓ 原创内容编写、素材授权、家长隐私要求、人工审核
未来的可玩题包与原创故事
        ↓ 完成证据核验、奖励登记、一次性领取
星星等奖励
```

## 三份映射文件

| 文件 | 输入 | 输出与边界 |
|---|---|---|
| `vocabulary-game-map.json` | [Unit 1 词汇](../miniprogram/curriculum/imports/unit1/vocabulary.json)的 40 个词条 | 每个词条保留稳定 ID、语义类别、候选小游戏类型和目标关联；`hello` 单列为 Welcome 先修词示例，尚无正式 Welcome ID。 |
| `sentence-game-map.json` | [Unit 1 句型](../miniprogram/curriculum/imports/unit1/sentences.json)的 14 条候选 | 只给出剧情对白意图、互动任务类型和口语练习方式，不写剧情台词。 |
| `objective-story-map.json` | [Unit 1 教学目标](../miniprogram/curriculum/imports/unit1/learning-objectives.json)的 4 项目标 | 给出任务意图、完成证据、团团的陪伴方式和冒险目标；星星只作待登记奖励候选。 |

三个映射文件都用 `textbookId + unitId + 知识点 ID` 定位内容。映射项的 `sourcePointer` 指向 Sprint 3.5-A 导入项；原始 PDF 位置保存在该导入项的 `source` 或 `sources` 字段。审校时沿“映射 → 导入项 → 原件页码”核对，不凭英文拼写自动合并不同教材、年级或册别的数据。

## 玩法选择

- `listen_match`：听音匹配文字或经授权的画面；必须先有已授权录音。功能词不能机械地配一张图片。
- `character_dialogue`：在**原创**人物交流中选择合适表达，保留团团温暖、鼓励、像朋友一样探索的角色规范。
- `context_choice`：依据原创情境选择词义、人物关系或用法，适合代词、介词和其他功能词。

这些是内容类型名，不宣称现有 `find-cookie` 小游戏已经支持。素材缺失时映射仍可供策划审阅，但不得发布为可玩题。口语练习目前只描述跟读或引导表达意图，默认不采集、不保存儿童声音；未来若启用录音或识别，需先明确家长授权和数据处理规则。

## 奖励与去重

`rewards: ["star"]` 表示该词可参与对应教学目标的星星奖励设计，**不表示答对这个词立即发奖**。每项目标须有经审核的完成证据、奖励目录登记和一次性领取键；同一学习者对同一教材、单元和目标最多领取一次。已有第一章星星与米米解锁仍由原系统管理，本映射不引用或修改其奖励 ID。

## 审核与发布门槛

1. 人工复核教材版本、Welcome 与 Unit 1 的边界，以及导入项的原文和位置；当前导入项仍为 `pending_human_review`。
2. 检查单词和句型是否适合拟定玩法；对 `here` 的两种释义分别审校，避免题目歧义。
3. 只使用原创或已获授权的情境、图片和音频；教材 PDF 原件和长段课文不进入运行时资源。
4. 独立创作、审核剧情及儿童反馈文案。团团是陪伴伙伴，不是老师，也不是宠物。
5. 审核目标达成条件、家长端可见摘要、隐私与奖励去重后，再由后续阶段明确接入。当前所有映射均为 `enabled: false`、`proposal_only`，不会生成题目、剧情或奖励。

新增教材或年级时，为每本教材建立独立命名空间，重复“来源定位 → 人工审校 → 映射 → 发布审核”流程；不复用本单元的知识点 ID 或把模拟教材当成真实教材依据。
