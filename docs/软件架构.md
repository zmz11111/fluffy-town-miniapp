# 软件架构设计

## 1. 架构目标

以微信小程序为首发客户端，先支持本地内容与进度，再通过边界清晰的接口接入云开发。内容、游戏规则和学习规则不依赖具体云厂商，便于后续扩展和测试。

## 2. 逻辑分层

```text
表现层（页面、组件、导航、无障碍提示）
        ↓
应用层（用例：开始学习、提交答案、结算奖励、同步进度）
        ↓
领域层（课程、题目、复习、宠物、剧情、小游戏规则）
        ↓
基础设施层（本地仓库、音频/资源、微信 API、云服务适配器）
```

页面仅负责呈现与用户事件；应用服务协调用例；领域模块维护规则；基础设施实现存储、网络和微信平台适配。内容通过 JSON/静态资源加载，生产环境可换成版本化内容包或云端只读服务。

## 3. 主要模块

- **学习内容**：课程树、词条、题目、提示、资源引用、来源与内容版本。
- **学习流程**：会话、答题判定、反馈、知识点掌握状态、复习计划。
- **宠物与奖励**：宠物状态和外观解锁；消费学习事件产生非惩罚式奖励。
- **剧情**：节点、条件、对白与资源；条件检查由进度状态驱动。
- **小游戏**：通用关卡生命周期与题目适配器，小游戏不复制学习判分规则。
- **进度与同步**：本地优先存储、变更队列、云端同步端口、冲突策略。
- **家长与隐私**：授权说明、数据查看/删除入口预留，按后续合规评估实现。

## 4. 运行与数据流

1. 页面请求课程单元，内容仓库返回本地缓存或已发布内容包。
2. 学习用例创建 session，题目引擎提供题目并计算结果。
3. 学习事件写入本地进度仓库；宠物/剧情模块订阅已完成的领域事件并更新解锁状态。
4. 若用户启用云服务且网络可用，同步适配器上传增量记录；服务器鉴权并按版本保存。
5. 内容更新走独立发布流程：候选导入 → 编辑审核 → schema 校验 → 版本发布 → 客户端拉取。

## 5. 云开发边界

初期定义 `ContentRepository`、`ProgressRepository`、`IdentityProvider`、`SyncService` 等接口。微信云函数/数据库只由基础设施层调用。客户端不得信任本地成绩作为云端权威奖励；服务端需要校验可验证的事件与请求限流。无账号方案确认前，默认只用本地匿名档案，不生成可识别身份。

## 6. PDF 内容导入

PDF 不直接作为运行时教材数据库。导入链路建议：版权确认 → 文本/图片抽取 → 结构化候选（单元、词条、例句）→ 人工英语与年级审校 → 音频/图片授权检查 → schema 校验 → 内容版本发布。扫描件 OCR 和断行/表格识别可能出错，自动抽取不能直接面向儿童发布。保留来源页码、文件版本、审校人和授权依据。

## 7. 关键决策与演进

- MVP 以小程序原生能力和轻量 TypeScript 模块为主，避免初期引入重型跨端框架。
- 本地数据采用可迁移 schema；云端按同一业务模型映射，不让页面直接依赖云数据库结构。
- 可先用静态内容 JSON 验证学习闭环；后续可加入内容后台、同步和分析，但分析数据先通过隐私审查。
- 埋点默认关闭或最小化；不采集自由语音、精确定位、通讯录等无关数据。

## 8. 质量属性与设计约束

稳定 ID、幂等进度写入、内容版本兼容、超时与离线降级、错误提示可恢复。配置与密钥通过本地忽略文件/环境配置管理；生产密钥绝不放入小程序包。网络 API 均需校验输入、权限和数据归属。
