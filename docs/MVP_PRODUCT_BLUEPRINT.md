# 《团团和它的毛茸茸朋友》MVP 产品蓝图

> 状态：路线冻结基线，待产品审核。本文用于约束 MVP 范围和系统职责；未经审核的 V2 想法不视为已排入开发。

## 1. 产品核心目标

为小学三年级英语初学者提供一段短小、可独立理解、允许反复体验的微信小程序学习冒险。孩子在团团的陪伴下完成一个明确的英语学习目标，通过剧情和小游戏练习词句，获得积极反馈，并看见自己的进度。

**MVP 成功的核心判断**：目标儿童能知道当前要做什么，能把学习任务与冒险目标联系起来，完成或暂停后能恢复进度，并愿意自发继续、复习或稍后回来。答题数量和停留时长不是成功的替代指标。

### 产品边界

- 首发平台：微信小程序；优先本地运行和本地保存。
- 首期用户：小学三年级英语初学者；内容先选定一个经过核验的教材版本与主题单元。
- 角色关系：团团是聪明、温暖、调皮的陪伴伙伴，不是宠物或老师。米米是剧情中的伙伴，不作为成绩或惩罚手段。
- 学习方式：学习目标是产品核心；剧情、小游戏、伙伴回应与奖励服务于理解、练习、复习和继续意愿。
- 内容要求：来源、授权、适用年级和人工审核可追溯。教材 PDF 是候选来源，不是直接发布的运行时内容。
- 数据要求：只保存完成体验所需的进度；默认不收集真实姓名、原始语音或其他无关身份信息。

Alpha 0.2 已有首页、团团点击互动、第一章五幕、听音找图、星星奖励、米米解锁和本地存档。该试玩闭环可作为 MVP 骨架；模拟样例和 Alpha 完成状态不代表正式教材内容已审核或真实儿童体验已验证。

## 2. 用户体验闭环

```text
打开小程序／继续上次进度
        ↓
首页看见团团、当前目标和清楚的下一步
        ↓
进入短剧情：角色说明我们要发现什么
        ↓
完成一个英语微任务：听、看、选或说
        ↓
团团解释发现；答错可重听、看提示或暂停
        ↓
任务结果改变故事或打开下一段内容
        ↓
获得有来源的星星／伙伴里程碑，进度自动保存
        ↓
回顾、继续下一段或结束；下次可恢复
```

### MVP 闭环验收

1. 首屏能展示欢迎、当前学习目标和开始／继续入口；角色互动可被发现，不依赖说明书。
2. 一章短剧情至少有一个与目标知识点相关的任务门槛，孩子能说出任务与故事的基本关系。
3. 一种小游戏可完成任务判定；错误不扣奖励，提供可理解的重试或提示。
4. 任务完成后有与当前情境相关的反馈，剧情或进度有可见变化。
5. 星星和伙伴奖励有清楚来源，重复进入不重复领奖。
6. 离开或关闭后重新进入，学习、章节和小游戏进度可恢复；完成后可自主停止。
7. 音频、图片或弱网出错时有文字或其他可操作退路，不把孩子困在无法继续的页面。

上述体验须由目标儿童的实际试玩验证。当前 Alpha 的代码级模拟走查不替代真机、可用性、教材和合规验收。

## 3. 四大核心系统

### 3.1 学习任务系统

**职责**：把课程知识点转成有目标、有操作、有反馈、有进度的短任务。一个任务说明“要学／练什么”和“为什么在当前冒险里做”。故事、小游戏是任务的体验载体；不各自复制学习判定、任务状态或奖励规则。

**MVP 范围**：一个主题单元；一个短任务链；一种主要练习交互。Alpha 现有听音选图作为起步样例。文字提示和重听属于该练习的可访问替代与辅助，不另算新玩法。提供适龄干扰项、友好反馈与简单复习入口。语音采集、复杂掌握度算法和自适应推荐不纳入冻结范围。

**状态与模块边界**：词句和题目是内容数据；答题结果、当前题目和完成事实是个人进度。英语／学习模块维护学习记录，小游戏模块维护回合判定，剧情管理器维护场景游标与任务触发。页面显示信息并提交选择，不直接写存档。

**验收重点**：儿童能用自己的话描述任务目标；答错后知道可做什么；任务使用的词句与已审校课程内容一致；中断后能恢复。

### 3.2 陪伴系统

**职责**：通过情境回应、共同探索和角色关系帮助孩子理解目标、降低挫败并连接故事。团团不能以照料、服从或成绩评定来换取情感回应。

**MVP 范围**：团团的有限情境对白、基础表情／动作、可发现的打招呼互动；米米作为第一章的剧情伙伴，在章节完成后加入。回应依据真实的剧情、任务或互动状态；没有匹配情境时用简短兜底语。

**状态与模块边界**：角色静态设定与对白在角色内容层；互动与伙伴解锁状态由角色／游戏状态模块管理。历史目录 `pets/` 是已有兼容边界，不能因此将团团重新定义成宠物；无需为产品命名而重命名目录。

**明确禁止**：答错降低友谊、离开后伙伴生病／失望、连续签到维系关系、无限点击刷好感、假装知道孩子的真实心情。成长主要通过章节里程碑、对白或可见内容变化呈现。

### 3.3 奖励成长系统

**职责**：让完成学习探索后的收获可见，并帮助孩子回想自己做成的事情。奖励是反馈，不是学习目标的替代物。

**MVP 范围**：可解释的星星里程碑、第一章伙伴解锁，以及少量预留物品／家具／成就类型。Alpha 现有小游戏 2 星、章节 5 星与米米解锁可用于闭环验证。奖励必须绑定稳定 ID、清楚来源并可去重。

**冻结决策**：MVP 只累计和回看星星，不建设商店、星星消费、价格、随机抽取、限时奖励或付费。未来若要让星星兑换物品，须另行评估状态模型、获得／消费账本和旧档案迁移，不能直接把现有累计值重新解释为余额。

**验收重点**：儿童看得见获得了什么及原因；章节重进不会重复增加星星；没有奖励时也能复习；奖励不羞辱、不排名、不制造错失焦虑。

### 3.4 教材融合系统

**职责**：将有权使用、适合目标年级、经人工校对的教材知识点提供给学习任务、剧情和小游戏。保持教材内容、故事创作与个人进度分离。

**MVP 范围**：先选定一套教材的一个年级／册别／单元，建立版本化结构和少量已校对词句。教材文件导入只产生候选项；来源页码、版权状态、适用范围、人工审核状态与音画授权在发布前可查。

**延展规则**：稳定 ID 与 `textbookId`、版本、年级、册别、单元和知识点关联；教材切换时不得仅凭英文拼写合并掌握记录。未来多教材、多年级复用 schema 和适配接口，内容审核和授权仍逐包进行。

**不属于 MVP**：任意 PDF 自动解析后直接发布、AI 自动编写正式剧情、未审核的真实教材批量导入。

## 4. 开发顺序

以下顺序描述依赖与决策门。Alpha 已实现的模块视为起点，不代表要按此顺序重做。

| 顺序 | 阶段 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 0 | 内容与体验定界 | 确认目标儿童、教材版本／授权、一个单元、学习目标、角色语气和隐私边界 | 内容范围与使用权有负责人确认；无法确认的内容继续使用原创演示资料 |
| 1 | 小程序壳与稳定状态边界 | 页面导航、模块职责、内容 schema、本地档案和错误退路 | 页面不直接改领域状态；ID 与档案版本规则明确 |
| 2 | 学习任务闭环 | 词句展示、音频／文字替代、一个可恢复练习、反馈和简单进度 | 目标儿童能理解目标与操作；重复事件不造成错误进度 |
| 3 | 陪伴和剧情闭环 | 团团情境回应、一个短章节、一个伙伴里程碑 | 剧情能解释任务目的；不依赖关系惩罚或复杂系统 |
| 4 | 奖励与成长呈现 | 星星来源、完成反馈、一次性伙伴解锁和进度回看 | 获得逻辑可追溯、领奖幂等、旧状态不丢失 |
| 5 | 教材发布与体验验证 | 经校对的单元内容包、儿童试玩、真机兼容、隐私和平台检查 | 体验、内容权利、数据处理和运行风险经负责人审核 |

云开发、账号和跨设备同步必须经过独立隐私及产品决策门；本地学习闭环不能以云端可用为前提。家长端、更多年级和更大内容库在 MVP 通过验证前保持规划状态。

## 5. 暂不开发内容

冻结期内不纳入 MVP 范围：

- 更多正式章节、分支剧情、多人／社交、排行榜、公开分享。
- 多宠物照料、团团喂养、好感刷取、定时照料或连续签到机制。
- 商店、星星消费、随机掉落、付费、广告或限时促销。
- 复杂等级／数值体系、无限收集、装饰编辑器或动画演出引擎。
- 自动选题、复杂自适应难度、自由语音识别、AI 对话或自动生成正式剧情。
- 任意教材 PDF 自动解析并直接发布、批量抓取教材或未经授权的图文音频。
- 多教材、多年级的完整商品化目录；先用单包数据结构验证扩展边界。
- 家长端、账号、云同步、云端内容后台和生产分析埋点。
- 为功能改名而改目录、重写现有系统、替换 Alpha 存档或一次性清理历史状态。

若法律、平台政策或儿童安全审查要求超出现有范围的保护措施，作为合规阻断项单独评估，不能视为普通功能扩展。

## 6. 架构稳定性检查

### 6.1 当前稳定边界

| 边界 | 冻结约定 | 当前对照 |
| --- | --- | --- |
| 页面与业务 | 页面展示并收集交互；领域模块负责学习与游戏规则、状态；页面不直接写 `wx` 本地存储。 | Alpha 页面调用学习、剧情、游戏、角色和奖励模块；保留此约定。`guidance/welcome.js` 单独保存首次欢迎是否已读的纯界面标记，不进入学习或游戏档案；这是当前已知的界面状态例外。 |
| 内容与进度 | 静态内容、来源和版本与单个孩子的状态分开保存。 | `curriculum/`、`story/`、角色对白与本地档案分离。 |
| 学习与游戏 | 学习目标由内容／任务引用；游戏管理自己的题目与回合；提交结果后推进任务。 | `games/find-cookie/`、`story-manager`、学习记录保持各自职责。 |
| 奖励 | 只领取目录登记的奖励 ID；奖励按 ID 去重；页面不传入任意奖励数量。 | `reward-manager` 维护星星和米米解锁；MVP 不改变为消费余额。 |
| 存档 | 统一校验和持久化；schema 变化有显式迁移；重进可恢复。 | 当前本地 schema v4，键为 `fluffy-town:local:v4`；新字段必须兼容已有记录。 |
| 教材融合 | 候选抽取、授权与人工审校在发布边界完成；运行时只引用已审核内容 ID。 | 当前课程样例和映射草案不自动改动 Alpha 游戏／奖励内容。 |
| 微信／云服务 | 微信 API 在基础设施边界使用；本地优先，云端作为后续适配。 | 当前不需要云环境运行 MVP；不把云同步写入首期验收前提。 |

### 6.2 稳定性结论

现有架构已具备按内容、任务、游戏、角色、奖励和存储划分职责的基础，足以支撑**一个课程单元、一段剧情、一款小游戏和本地进度**的 MVP。冻结方向应通过内容配置与有限的模块适配推进，不需要推翻架构。

本蓝图**不是**代码审计、真机测试报告或兼容性证明。正式进入实现前，仍需核对存档迁移、页面生命周期、资源授权、教材内容准确性及目标机型。历史 `pets/` 路径与 `petState` 命名属于兼容债务；在没有明确迁移需求时保持稳定，产品模型继续把团团定义为陪伴伙伴。

### 6.3 路线冻结与变更规则

以下决定作为基线：目标用户与核心目标、单元级内容规模、学习任务闭环、四大系统职责、状态所有权、奖励非惩罚原则和本地优先。新增想法先进入待评审区，不默认进入 MVP。

提出变更时须附：

1. 对应的儿童观察、内容要求、平台／安全问题或明确业务价值；
2. 要改动的用户流程和四大系统；
3. 涉及的稳定 ID、档案字段、迁移和历史存档处理；
4. 新增的素材来源／授权、失败退路与验收方式；
5. 对开发顺序和 MVP 时间／范围的影响。

仅当变更解决已观察到的阻断问题、必要合规要求，或经产品审核明确取代一项现有范围时，才更新冻结基线。否则保留在后续版本，不为局部反馈重写模块边界。

## 冻结前仍需产品负责人确认

1. 具体首发教材版本、册别、单元及该资料用于产品的授权范围。
2. Alpha 0.2 儿童真实试玩记录与核心流程是否满足继续意愿目标。
3. 首发隐私告知、监护人授权、数据保留／删除及微信平台要求的审核结论。

这些确认项不改变上述架构边界；在未确认之前，正式教材发布、账号云同步和面向公众上线保持未批准状态。
