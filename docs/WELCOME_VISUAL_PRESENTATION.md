# Welcome 视觉表现（Sprint 12-A）

## 接入范围

Welcome 剧情与学习页共用 `components/welcome-scene` 原生展示组件。背景和角色在上方，对话框在下方自然换行，避免长对白遮挡角色。学习选项、音频播放、完成按钮及原有防连点逻辑沿用现有处理函数。

组件没有事件触发任务完成，也不读取或保存学习进度。页面根据当前课程步骤、场景、反馈和已收到的奖励结果传入展示参数；展示米米不代表已经解锁伙伴。Unit 1 保持原页面分支和原图片接口。

## 角色与动画

- 团团沿用四态图片；`curious/worried` 映射思考图，成功反馈使用开心图。
- 米米使用原待机头像与三张新增原创表情图：思考、开心、惊喜。错误反馈表现为共同观察，完成奖励表现为惊喜，不责备孩子。
- 场景或学习步骤 ID 改变时，背景短暂淡入约 0.3 秒，角色淡入约 0.45 秒；同一步重听不重新创建场景。
- 只有页面收到 Welcome 完成奖励反馈时才播放约 1.2 秒的星星上升动画，动画不会调用奖励接口。后续回首页的树屋成长提示仍按原展示记录处理。
- 不使用持续循环动画，不等待动画结束才开放操作；系统支持减少动态效果时显示静态画面。
- 图片失败时保留树屋占位、角色姓名和对话，任务操作继续可用。

## 资源需求与替换

本阶段不要求外部资源：已有树屋、团团与米米待机图继续使用，新米米表情由项目脚本绘制。全部资源来源已登记在 [素材来源.md](素材来源.md)。

后续正式原画可交付米米 512 × 512 透明 PNG 的 `idle/happy/thinking/surprise` 四态，统一耳朵位置和面部比例；当前三张新增图为几何占位。替换路径集中在 `assets/welcome-visuals.js`，团团与背景继续使用 `assets/visuals.js`。不要把英语答案、教学目标或课程编号绘制进图片，方便多教材、多年级复用。新增背景或动作原画需另行评审，本阶段不增加地图或玩法。

## 验证

自动化测试覆盖展示组件不写存档、表情资源有效、缺图降级、Welcome 首课挑战与奖励保持原规则。微信开发者工具仍需人工查看：首次进入、听音、错误重试、成功反馈、完成奖励、两幕剧情转场，以及小屏长对白换行。
