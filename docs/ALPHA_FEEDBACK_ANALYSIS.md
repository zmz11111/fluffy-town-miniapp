# Alpha 0.2 体验反馈分析（待审核）

## 证据边界

本项目目前有 [试玩指南](ALPHA_PLAYTEST_GUIDE.md) 和 [反馈记录模板](PLAYTEST_FEEDBACK_TEMPLATE.md)，尚未收到已填写的儿童试玩记录、访谈原话或观察数据。因此，“团团生命感不足”“打招呼互动”“星星价值”“答题感较强”是本轮产品讨论的**反馈主题**，并非已经统计证实的儿童结论。以下把可从现有版本确认的事实与设计推断分开；待真实记录到位后按测试者代号、环节、原话和重复次数复核。

| 主题 | 现有版本事实 | 需要试玩验证的问题 |
| --- | --- | --- |
| 团团生命感 | 首页有首次欢迎、随章节状态变化的短对白；点击团团会换短暂表情、显示 Toast，并累计互动次数。剧情情绪随场景变化。 | 孩子是否把团团看成会回应当前冒险的伙伴，还是一次性按钮？是否注意到表情与对白变化？ |
| 打招呼 | 当前首页单次点击会挥手并计数；米米解锁后可在伙伴页打招呼。 | 孩子是否主动点团团？点击后是否想再次交流？是否理解团团与米米的不同身份？ |
| 星星价值 | 第一章小游戏发 2 星、章节发 5 星；完成卡片展示数量，奖励按 ID 防重复。现阶段没有明确用途。 | 孩子能否说出星星从何而来、可以用来做什么？数字增加是否足以形成继续探索的期待？ |
| 英语小游戏 | 第三幕要求完成三轮听音选图才能推进；答错可重听，完成后回故事。 | 孩子能否说出为何找这三张图、线索如何帮助找到饼干，还是只觉得在做题？ |

## 1. 团团角色生命感不足

### 可能原因

- 首页欢迎只出现一次；普通点击的主要反馈是固定挥手 Toast 和累计次数。孩子的行为、当前场景、最近共同发现之间缺少可见的因果回应。
- 剧情有情绪字段和对白池，但首页互动与这些上下文联系较弱；表情变化约一秒后恢复，可能来不及被注意。
- “累计互动次数”属于系统记录，不能代替角色关系。反复点击若得到同一句话，容易被理解为普通按钮。

### 设计方向

让团团基于**真实已知状态**回应：初次见面、正在找线索、刚完成小游戏、米米加入后，各有一句短对白和匹配表情。回应应包含“我看见了什么／我们下一步可以做什么”，允许孩子选择继续或暂停。可在每个情境中准备少量人工审核的变体，保留稳定兜底文案；不需要生成式 AI，也不假装知道孩子的情绪或现实经历。

团团始终是并肩探索的智能陪伴伙伴，不能被设计成需要喂养、依赖连续登录或靠好感度驱动的宠物；也不以老师口吻点评孩子。具体文案须遵守 [团团角色设计规范](GAME_DESIGN.md)。

### 验证方式

观察孩子是否主动再次触碰团团，能否说出“团团知道我们刚做了什么”，以及是否愿意与它一起继续。记录原话与停顿，不以点击次数或停留时长单独证明喜爱。

## 2. 打招呼互动机制

建议把“点团团”明确成一次**打招呼**：轻触 → 团团看向孩子或挥手 → 一句与当前情境有关的回应 → 可选择继续冒险。首次点击可给出更清楚的互动暗示；后续不强迫每日签到，也不因长时间未打开而让团团失望。

| 情境 | 回应意图示例 | 应避免 |
| --- | --- | --- |
| 初次见面 | “嗨，我是团团。你想先看看树屋吗？” | 长篇教程、命令开始学习 |
| 寻找线索中 | “那几张图卡还在等我们。要一起去看看吗？” | 把孩子返回首页说成放弃任务 |
| 找齐线索后 | “我们找到三条线索啦，米米一定想听。” | 只报“正确 3/3” |
| 第一章结束 | “米米来了！想去和她打个招呼吗？” | 用重复点击刷奖励或亲密度 |

互动可以记录用于恢复体验，但不把点击数兑换成星星、英语能力或团团的“爱”。对米米的友谊里程碑仍由有意义的剧情事件驱动。下一版先验证**一次点击是否被孩子理解、回话是否贴合情境**，再决定是否增加多轮互动。

## 3. 星星奖励价值体系

当前星星有清晰的发放时点与去重规则，却只有数量展示，缺少孩子可感知的意义。建议保留 `stars` 与 `claimedRewardIds` 作为既有事实，不改写旧档案；产品层先定义星星为“共同发现的纪念”，再设计用途。星星不能成为答错惩罚、付费兑换或无限点击收益。

| 层次 | 建议的儿童感受 | 设计规则 |
| --- | --- | --- |
| 获得 | “我们找齐线索，点亮 2 颗星；完成故事，又点亮 5 颗。” | 每个奖励有来源、一次性领取 ID；说明与发现的关系。 |
| 看见 | 章节结束有简短的获得说明，首页或树屋有可回看的星星进度。 | 同一笔奖励只出现一次；重玩可复习，不重复加星。 |
| 使用 | 候选方向：累计星星点亮树屋的固定装饰或冒险纪念册页。 | 优先做可预览、可解释、不可随机的里程碑；不消耗既有星星，先让孩子理解。 |
| 长期 | 新章节可有新的纪念目标，但不靠每日签到积累。 | 教材、年级、章节奖励 ID 分开；跨版本要解释已有记录。 |

**待决策点**：优先验证“非消耗式里程碑”是否让星星有意义。若以后考虑购买式花费，须另行设计余额与总获得量、撤销及迁移规则，并经家长与儿童测试；本轮不提出实施。

## 4. 英语小游戏从答题转为冒险任务

现有小游戏已由第三幕触发，回合与任务完成也由管理器保存。体验上的关键缺口可能在**题目与故事线索的对应关系**：孩子点击图片后看到答对反馈，却未必知道这张图怎样缩小了寻找饼干的范围。

建议保留“听音选图”的操作和正确性判定，把每轮包装为一个可见的探索动作：

1. 进入任务前，米米提出具体问题，例如“听到的词会告诉我们先看哪里？”
2. 每轮目标词对应故事场景中的一个可识别线索物；孩子选中后，团团说出词与线索的关系，而不只说“找到了”。
3. 三轮完成后，线索汇成一个简单结论，回到第四幕由角色据此找到饼干。孩子能看到自己的选择推动故事。
4. 答错时提供重听或视觉提示，不倒计时、不扣星；声音不可用时保留文字退路。

可从第一章的词与图开始做内容审阅，不直接把任意教材词硬塞进饼干线索。未来 PDF 内容须先确认使用权、保留来源位置并人工校对，再由 `curriculum/game-mapping/` 提供知识点候选；剧情作者确认叙事合理性后，才交给 `story/` 与小游戏内容模块。多教材、多年级可换题包与提示密度，任务判定仍归业务模块，页面不直接写状态。

## 后续证据需求

下一轮至少汇总每位测试者的环节完成情况、是否主动触碰团团、孩子如何解释星星、能否说明图片与饼干的关系，以及“愿意／不确定／不愿意继续”的原话。按重复问题和影响程度确定优先级；没有记录前，不把任何单一推断当成产品定论。实施顺序与审核门槛见 [V2 产品计划](V2_PRODUCT_PLAN.md)。
