# 《团团和它的毛茸茸朋友》视觉设计系统（Sprint 4-A）

> 状态：视觉规范草案，供原画、UI 与内容审核使用。本阶段只建立规范，不替换 Alpha Demo 资源，不修改页面、剧情、游戏或状态代码。团团的人格和对白以 [团团角色设计规范](GAME_DESIGN.md) 为准；素材使用权以 [素材来源](素材来源.md) 为准。

## 1. 产品视觉定位

**关键词：温暖树屋、毛茸茸伙伴、好奇探索、清晰易读。**面向小学三年级儿童，画面像一本可以轻触的森林故事书：形状圆润、材质有轻微纸张和绒毛感、光线柔和，关键操作始终清楚。画面传达“我们一起发现”，不用考试卷、排名榜、惩罚图标或制造焦虑的红色警报。

- **可爱 50% / 聪明 30% / 调皮 20%**是团团的整体气质，不是每张图的机械配比。角色可以好奇地歪头、拿着线索卡，但不扮演老师。
- **视觉密度**：一屏一个主要目标；背景装饰不能盖住文字、题目图片和按钮。成功反馈温暖轻快，失误反馈提供再次尝试的空间。
- **连续性**：保留 Alpha Demo 的奶油底色、森林绿主按钮和树屋轮廓。未来替换素材时逐页替换并验收，不一次性改掉所有页面。
- **成长适配**：更高年级可增加信息量和线索复杂度，角色轮廓、色彩语义和按钮位置保持稳定。不同教材的封面或主题装饰只作为内容皮肤，不改变基础交互。
- **家长端预留**：未来家长端沿用同一色系，但降低角色装饰密度，突出来源、进度和隐私说明；不把儿童的学习表现画成排名或负面标签。

## 2. 世界观与场景语言

故事发生在**毛茸茸小镇**。树屋是起点和安全的归处；小路、草坡、朋友的小屋与发现线索的角落向外延伸。场景以日常可理解的物件为主：树叶、木桥、篮子、布旗、图卡。奇妙感来自细小发现，而不是危险、战斗或强烈闪烁。

| 场景层 | 设计方式 | 使用原则 |
|---|---|---|
| 远景 | 柔和天空、山丘、树冠，大色块低对比 | 只交代地点和时间，不承载关键信息 |
| 中景 | 树屋、路径、家具、可识别的线索位置 | 同一物件在不同页面保持形状与颜色连续 |
| 前景 | 角色、可交互物件、对话卡和按钮 | 轮廓清晰；不能依赖背景颜色辨认 |
| 氛围 | 少量叶片、暖光、纸张纹理 | 不覆盖英文、中文释义、音频回退文字 |

白天为默认展示；黄昏等变体只改变环境光和装饰，不改变按钮颜色的语义。小屋页属于**后续页面规划**，本阶段只有视觉规范，没有页面实现。

## 3. 角色设计规范

所有角色先画黑白剪影，再做色彩和表情：缩至 128 × 128 像素仍能区分团团、米米、布丁。眼睛、口型和手势要在小屏幕上看清。儿童答错时不得让角色露出责备、失望或惊吓的表情。

### 团团 Tuantuan

| 方面 | 规范 |
|---|---|
| 身份 | 毛茸茸的小熊；孩子的智能陪伴伙伴，不是宠物、老师或裁判。 |
| 外形 | 近圆形头和躯干、短圆耳、奶油色口鼻区、暖焦糖棕绒毛。可有一条低饱和森林绿小围巾作为识别点；不配教鞭、成绩册或权威制服。四肢短但能做清晰的指向与挥手动作。 |
| 性格表现 | 好奇时先观察，再邀请孩子一起看；聪明体现在发现细节，调皮体现在轻巧的小动作，不以嘲笑或夸张卖萌表达。 |
| 表情 | 基础：平静、好奇、高兴、轻微担心、兴奋。现有情绪状态 `curious / happy / worried / excited` 需各有可辨图；`worried` 是关心线索，不是恐惧或责备。眨眼和嘴角变化应克制。 |
| 动作 | 待机轻呼吸、眨眼、歪头、挥手、指向线索、找到线索后轻跃。动作结束回到待机姿态；不要持续跳动妨碍阅读。 |
| 对白关系 | 面向孩子或伙伴，站在同一探索视角。反馈图不能出现红叉指责、低分牌或“必须完成”的姿态。 |

### 米米 Mimi

| 方面 | 规范 |
|---|---|
| 身份 | 橘色小猫、聪明好奇而略傲娇的侦探伙伴；第一章完成后加入。 |
| 外形 | 修长一点的猫形剪影、三角耳、橘金色毛与少量深橘虎斑、奶油色胸口、细长弯尾。眼神机灵，耳尖和尾巴是主要表演部位；侦探感可通过小布包或叶形线索夹表达，不依赖借用已有 IP 的服装。 |
| 性格表现 | 先自信地发现细节，再愿意和团团、孩子分享；略傲娇是轻微的表情停顿和尾巴动作，不挖苦孩子。 |
| 表情与动作 | 观察、疑惑、得意、友好、加入伙伴。可短暂眯眼、抬眉、尾巴轻摆、俯身看线索；解锁前的展示应说明尚未加入，不使用恐怖剪影。 |

### 布丁 Buding（待确认提案）

布丁目前没有既定角色数据、剧情或玩法。以下仅供角色视觉评审；确认物种和性格后才能进入正式资产清单。

| 方面 | 提案 |
|---|---|
| 外形 | 奶油色垂耳小狗，耳尖和尾巴带浅焦糖色，脸颊像蓬松布丁一样圆软；一只耳朵略高、一只略垂，尾巴短卷。与团团的圆耳、米米的三角耳形成明显剪影差异。 |
| 性格表现 | 温和、细心、稍慢热，喜欢一起分享发现；高兴时小幅摇尾，思考时歪耳。不能被写成需要孩子照料才不难过的角色。 |
| 边界 | 不规定解锁方式、好感度、教学职责或正式对白。未来确认后再设计动作和页面接入。 |

### 角色共通交付

每位正式角色至少交付正面与四分之三侧面、背面结构参考、色板、五种基础表情、待机与招呼动作关键帧。比例、耳尾位置、围巾或配件的锚点保持一致；同一角色不同表情不能改变头身比。小图只保留必要面部特征，避免细纹在手机上糊成一团。

## 4. UI 设计规范

### 基础样式与可读性

| 用途 | 建议色值 | 说明 |
|---|---|---|
| 页面底色 | `#F8F3E8` | 沿用 Alpha Demo 的暖奶油色 |
| 卡片底色 | `#FFFDF7` | 文字与场景的安静承托层 |
| 主文字 | `#304D3C` | 标题和重要信息 |
| 次要文字 | `#5B6C60` | 说明和辅助信息；发布前核对对比度 |
| 主操作 | `#3D6B4C` | 延续森林绿方向，优先满足白字可读性；未来实现时再逐页替换现有色值 |
| 暖色强调 | `#F6DFA9` | 星星、发现、温暖光点，不单独表示答对 |
| 温和提醒 | `#A64F41` | 仅用于需要注意的信息，必须同时配文字 |

- 以 750rpx 设计稿为布局参考；内容区在窄屏上仍有边距。主要操作按钮建议高度至少 88rpx，图卡触控区建议至少 100 × 100rpx，避免小目标密集排列。
- 中文正文字号建议 28–34rpx，英文目标词或关键对白可更大；说明文字不低于 24rpx。标题、正文、按钮的层级通过字号与留白建立，不只靠颜色。
- 文案可换行，留出英文长词、动态数字和系统字体差异的空间。背景图上必须有实色或足够不透明的文字底板。重要信息的文字与背景对比度以 4.5:1 为审稿目标。
- 图片、颜色、音效至少有一种文字或形状替代。点击反馈不只闪色；动画可跳过，减少动态效果时保留状态变化。

### 页面构图

| 页面 | 主要视觉层级 | 关键规范 |
|---|---|---|
| 首页 `home` | 树屋场景 → 团团 → 今日任务 → “开始冒险” | 树屋是地标，团团可点击但不遮挡主按钮；任务进度要同时有数字和文字，进入剧情的入口在首屏清晰可见。 |
| 剧情页 `story` | 场景图 → 说话角色 → 一段短对白 → “继续故事” | 对话卡始终高于装饰层；同幕切换保持按钮位置稳定。情绪通过面部和姿态表达，不让插图替代对白。 |
| 小游戏页 `games` | 任务提示 → 播放/重听 → 大图选项 → 温暖反馈 | 选项大小一致且不靠颜色区分答案；音频不可用时显示文字回退。答错后允许重听，无倒计时压迫。 |
| 伙伴页 `pets` | 团团与米米角色卡 → 状态/加入信息 → 互动入口 | 团团卡写“陪伴伙伴”；米米未解锁状态仍可辨识。友谊信息不呈现为孩子的成绩。布丁未确认前不出现在运行页。 |
| 小屋页 `room`（规划） | 房间全景 → 可交互物件 → 简短说明 | 保留角色活动和文字区域；家具点击目标与背景装饰分层。未来的家长入口不得混入儿童奖励动线。当前没有此页面或家具玩法。 |

## 5. 图片与动画资源规范

### 画布、格式和安全区

| 用途 | 建议交付尺寸（像素） | 格式与注意事项 |
|---|---:|---|
| 角色设定母稿 | 至少 2048 × 2048 | 保留可编辑源文件与分层；源文件不直接打入小程序包 |
| 角色全身静态图 | 1024 × 1024 | 透明 PNG；角色统一地面基线，周围留 8%–12% 空白 |
| 角色头像/卡片图 | 512 × 512 | 透明 PNG；耳朵和配件不能被圆形裁切 |
| 表情特写 | 512 × 512 | 透明 PNG；与头像共用头部比例 |
| 首页/剧情横向场景 | 1500 × 900 | 原创背景优先 JPEG；需要透明前景层时用 PNG。中央 70% 保留主要物件，边缘可裁切 |
| 小屋竖向场景（未来） | 1500 × 2668 | 背景与家具分层；顶部状态区和底部按钮区不放关键线索 |
| 题目图卡 | 512 × 512 | PNG 或 JPEG；主体居中，纯图也应配可读的文字替代 |

尺寸是交付基准，不等于页面渲染尺寸；小程序内使用 `rpx` 和容器适配。输出前检查真实包体积、透明边、缩小后的识别度及设备显示。已有几何占位图继续保留，替换时逐张记录来源与授权。

### 命名与目录

统一使用小写 ASCII、下划线、稳定角色/场景 ID 和两位版本号，不在文件名中使用空格或中文；例如：

```text
miniprogram/assets/
├── characters/
│   ├── tuantuan/char_tuantuan_idle_front_v01.png
│   ├── mimi/char_mimi_curious_three_quarter_v01.png
│   └── buding/                 # 提案通过后才创建正式资源
├── scenes/
│   ├── treehouse/scene_treehouse_day_bg_v01.jpg
│   └── room/                   # 后续小屋页
├── ui/ui_star_reward_v01.png
└── animations/
    └── tuantuan/anim_tuantuan_wave_front_v01.png
```

目录树是**未来资源规划**，本阶段没有创建这些文件。角色 ID 使用 `tuantuan`、`mimi`、`buding`；朝向使用 `front`、`three_quarter`、`side`、`back`，动作使用 `idle`、`wave`、`point` 等固定词。正式替换时集中记录页面引用，避免同一语义出现多个临时文件名。

### 动画交付

- 动画按“角色 / 动作 / 朝向 / 版本”组织；若使用序列帧，所有帧画布尺寸、脚底基线、锚点和透明边保持一致。建议同时提供同名静态首帧，供低性能设备和减少动态效果模式使用。
- 动作建议短而可中断：待机眨眼、挥手、歪头等以 6–12 帧/秒的轻量节奏为起点；不做长时间循环跳动、强闪烁或突然放大的镜头。最终帧率以真机表现为准。
- 每个动画附同名元数据说明帧宽高、帧数、帧率、锚点、循环方式和静态回退图。正式资源接入前审核页面性能、音画同步和儿童可读性；本阶段不新增动画代码。

## 6. 素材审核与交付检查

1. 每张图和每段动画登记创作者、制作日期、源文件位置、使用许可、修改记录及审核人；未经授权的第三方角色、贴图、字体和配乐不得进入仓库。
2. 教材 PDF 导入的是待审校知识点，不自动取得封面、插图或人物形象的游戏使用权。若页面使用教材相关视觉，应另行核实授权。
3. 审核角色是否符合人格：团团不说教，米米不嘲笑，布丁不诱导照料压力；情绪和奖励不会因答错而惩罚孩子。
4. 审核 750rpx 设计稿在小屏、长文案、无音频、减少动态效果下的可读性。先给 Alpha Demo 做局部替换对照，再决定后续资源制作顺序。

**待确认项**：布丁的物种与正式身份、最终角色配色、页面插画风格样张、单张资源包体预算。这些决定需要美术评审后再落到代码和资产，当前不影响 Alpha Demo 运行。
