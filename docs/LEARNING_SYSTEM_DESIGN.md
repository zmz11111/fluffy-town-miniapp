# 学习系统设计（Sprint 5-A）

> 设计稿，待审核。本文件定义 MVP 学习体验与数据边界，不代表新增功能已实现。遵循 [MVP 产品蓝图](MVP_PRODUCT_BLUEPRINT.md) 和 [统一数据管理规范](DATA_STANDARD.md)。

## 1. 设计目标

让三年级英语初学者在一次短体验中知道“我在学什么、为什么要做、接下来可以做什么”。学习任务是主线；团团、故事、小游戏和奖励帮助孩子理解、练习和回顾。15 分钟是建议上限与设计节奏，不是必须完成的时长；孩子随时可以暂停，进度可恢复。

MVP 先围绕经确认的一套教材、一个单元和一种主要小游戏交互。Alpha 现有六个原创测试词与第一章仅作技术样例，不作为正式教材学习数据，也不能据此推断孩子已经掌握。

## 2. 每日 15 分钟学习循环

建议单次约 12～15 分钟。新授与复习可按孩子当前进度调整，不要求每次每类任务都完成。每个环节有结束点，不能以连胜或连续签到把孩子留在产品中。

| 时间参考 | 环节 | 儿童体验 | 结束时的感觉 |
| --- | --- | --- | --- |
| 0～1 分钟 | 打招呼与选目标 | 团团说明“继续上次”或“今天看一个小目标”；孩子可直接继续或稍后再来。 | 知道本次目标，可自主选择。 |
| 1～4 分钟 | 单词任务 | 接触 2～4 个新词或待复习词；结合声音、图像、词形和简短释义。 | 见过并尝试过目标词。 |
| 4～7 分钟 | 句型任务 | 在有意义的场景中听／读一个短句型，再完成一次选择、替换或排序。 | 知道句型在什么情境使用。 |
| 7～10 分钟 | 听力任务 | 听短音频，可重播；从少量清楚的选项中找出对应意义。 | 知道听懂的信息怎样帮助当前目标。 |
| 10～12 分钟 | 口语任务 | 跟团团轻声跟读或自主说一句；不想开口时可选择、默读或跳过。 | 体验表达，不担心被录音或评分。 |
| 12～14 分钟 | 复习任务 | 回看 1～3 个之前见过的词／句；给提示后允许再试。 | 重新想起内容，发现自己比上次更熟悉。 |
| 14～15 分钟 | 收尾 | 团团总结今天共同完成的事；显示进度与本次来源明确的奖励，可选继续／结束。 | 感到有完成感，清楚下次从哪里继续。 |

### 节奏规则

- 若当天只有少量时间，优先保留一个学习目标和一次复习，不把所有环节压缩成连续测验。
- “每日”是产品建议，不设置漏学惩罚、进度清零或伙伴失望状态。
- 新授、练习、复习分别标明；单次选择正确只代表这次完成，不直接标为长期掌握。
- 若学习活动在小游戏或故事里完成，计入同一知识点的学习经历，避免页面和小游戏分别建立重复记录。
- 音频不可用时给文字／图片退路；孩子可以静音体验。口语不以收集语音作为完成条件。

## 3. 儿童学习任务结构

### 通用任务组成

每个任务在策划和内容审核时至少说明：

| 要素 | 说明 |
| --- | --- |
| 任务身份 | 稳定 `taskId`、任务类型、内容版本；内容包和孩子进度分开。 |
| 学习目标 | 关联教材、年级、册别、单元、知识点 ID；明确是新授、练习还是复习。 |
| 儿童提示 | 一次只说一个动作；用三年级儿童能读懂的短句，可配语音但不只靠语音。 |
| 操作步骤 | 可见、有限的触控动作；提供重听、重看、提示或跳过选项。 |
| 完成证据 | 可观察的行为，例如选出匹配图片、完成一次情境选择；不把探索性指标称作能力结论。 |
| 反馈 | 团团或故事角色说明发生了什么以及下一步；答错不扣星、不减关系。 |
| 进度恢复 | 当前题目／已完成事实保存在任务状态；离开后可继续，不重复发奖励。 |
| 来源和资源 | 来源位置、授权状态、审核状态、音频／图像引用；素材未批准时任务不能发布。 |
| 数据边界 | 要保存的最少进度、保留期限和是否涉及音频；默认不保存儿童口语录音。 |

### 单词任务

- **目标**：识别词形与意思，建立常用词的声音、文字、图像或情境联系。
- **建议内容量**：每个短环节 2～4 个目标词；具体数量经儿童阅读和注意力观察调整。
- **操作例**：先听／看词，再选与词义相符的原创或已授权图片、人物或情境；随后在不同呈现中再遇到一次。
- **提示**：可重播声音、查看词形或看图；不要把拼写困难反馈成“不会英语”。
- **完成证据**：完成一次辨认或配对；之后可在复习中再次遇到。一次成功不等于长期掌握。
- **内容规则**：多义词按教材当前义项绑定独立 sense ID；同形词不以字面相同自动合并记录。

### 句型任务

- **目标**：理解句型用途，并能在一个清楚情境中认出或组织表达。
- **操作例**：听／读示例、选择适合说话场景的一句、替换一个已经学过的词，或排列少量词块。
- **提示**：先提供范例；不要一开始要求自由造句或长篇输入。缩写、标点和人称变化须经英语审校。
- **完成证据**：在指定情境下完成一次选择或组织。记录句型 ID 与情境，而不是保存孩子完整自由输入作为默认数据。

### 听力任务

- **目标**：听辨已学习的声音或简短句意，并把声音联系到词、人物、图片或故事线索。
- **操作例**：播放后选择；不限重播次数、不计时；选择后由角色解释词与线索的关系。
- **无障碍退路**：播放失败时显示目标词或文字提示；不能因静音、网络或设备问题判定孩子失败。
- **完成证据**：本次任务是否完成、使用了重播／提示与否（只有确有必要时记录）；默认不保存原始声音。

### 口语任务

- **目标**：降低开口压力，给孩子练习发音和表达的机会，不在 MVP 中做语音评分。
- **操作例**：团团先示范一个短表达；孩子可以跟读、自己说、默读／选择后继续。清楚显示“可以跳过”。
- **完成证据**：孩子主动点选“我试过了”或完成配套选择即可；不以录音、识别准确度、音量或口音判断奖励资格。
- **隐私边界**：MVP 默认不录音、不上传、不生成语音画像。任何录音或语音识别需另做监护人授权、保留／删除策略和专项审核，不属于本阶段设计批准。

### 复习任务

- **目标**：在稍后或不同情境再次遇到以前见过的知识点，帮助孩子回想。
- **MVP 策略**：使用“最近练过／本次刚学过／孩子选择再看”的简明候选；不先引入复杂间隔算法。可回答“再试一次”或“给我提示”。
- **完成证据**：完成一次回顾；错答只更新为需要再遇到，不删除旧记录、不改变伙伴关系。
- **选择边界**：同教材版本优先；教材切换后按稳定 ID 与人工维护的等价映射决定是否复习，不以拼写相同自动复用掌握状态。

## 4. 游戏化融合方式

游戏化是对学习目标的呈现，不应把知识点包装成无关点击或纯奖励门槛。

```text
审核后的知识点与目标
          ↓
学习任务（目标、操作、完成证据）
          ↓
剧情给出“为什么需要这个知识点”
          ↓
冒险中的小游戏呈现练习
          ↓
团团／伙伴回应孩子刚做出的发现
          ↓
任务进度与有来源的奖励写回统一状态
```

| 系统 | 融合方式 | 责任边界 |
| --- | --- | --- |
| 剧情 | 用角色遇到的问题引出学习目标；任务完成后剧情对孩子的发现作出回应。 | 剧情内容提供动机与上下文；任务是否完成仍由任务／小游戏规则判定。 |
| 冒险 | 把听、读、选或说转成找线索、认识伙伴、整理信息等有明确目的的行动。 | 不用虚假的紧急危险或倒计时迫使作答；错误后仍能继续。 |
| 陪伴互动 | 团团根据当前章节、任务完成事实或孩子主动打招呼给一句相关回应；米米可对共同发现作角色反应。 | 角色读取必要状态；不让好感度替代学习结果，也不伪造孩子的情绪。 |
| 奖励 | 完成已审核的学习里程碑后给明确星星或伙伴／内容解锁，并解释来源。 | 奖励目录和管理器去重；页面不能增加任意奖励。MVP 星星只累计与回看。 |

### 示例链路（仅设计示意）

学习目标是用英语问候新朋友。剧情交代团团和伙伴刚遇见；单词任务帮助认识问候词；句型任务让孩子判断哪句话适合初次见面；听力任务让孩子听出角色说了哪句；孩子可选择跟读；复习时换一位角色再遇到同一表达。完成任务后，团团和伙伴回应“我们认识新朋友啦”，状态模块记录任务完成；若本目标登记了星星奖励，则按稳定目标奖励 ID 发放一次。

此链路不能直接套用到未审校的单元内容；具体词句、完成证据、故事关系、资源权利须逐项审核。现有 Unit 1 游戏映射仍是 disabled／proposal，不会自动成为 Alpha 题目。

## 5. 三年级英语初学者适配原则

1. **少量呈现**：一屏一个主要动作；任务短；选项数量和干扰项难度逐步调节，不堆叠无关信息。
2. **短句与熟悉词**：按钮用动词短语；英文目标配简明中文支持；避免只靠长段说明或陌生术语。
3. **声音可控**：音频短、可以重听；孩子可暂停或静音；播放失败有文字和图像替代。
4. **触控清楚**：选项面积足、间距足；图片不只靠颜色区分；点击后有文字／形状／对白反馈。
5. **错误可恢复**：不倒计时、不扣星、不公开排名、不责备；错误后提供有用提示，允许自己再试。
6. **难度从内容决定**：由审校者按知识点与先备要求选择难度，不根据一次答题推断年级、能力或学习障碍。
7. **允许表达差异**：口语可跳过，不判断口音；答题输入尽量使用点选而非长文本；读写困难时保留听与图。
8. **尊重自主与休息**：每段结束给继续、复习或结束选项；不会因停止而丢失伙伴或已得进度。
9. **素材适龄且合规**：角色、画面和对白原创或经授权；教材候选在确认使用权和人工审核前不进入儿童发布包。
10. **家长端预留但不提前采集**：未来可读必要的目标与进度摘要；本地 MVP 不因预留家长端而多收孩子资料。

## 6. 学习数据记录设计

### 数据分层

| 层 | 记录内容 | 保存位置／用途 |
| --- | --- | --- |
| 内容知识库 | 教材、版本、年级、册别、单元、词义、句型、难度、来源页码、审核和授权状态。 | 版本化内容文件；不含儿童个人进度。 |
| 学习经历 | 知识点被展示、练习或复习的状态；学习目标和教材版本引用。 | 现有本地档案 `progress`／`learningRecords`；MVP 本地优先。 |
| 当前会话 | 当前任务、题目／回合游标和必要恢复信息。 | 现有 `gameState.currentGame` 或领域模块持有；离开后续玩。 |
| 奖励事实 | 已完成的里程碑、领取的奖励 ID、当前累计星星。 | 现有 `gameState` 与 `claimedRewardIds`；领奖幂等。 |
| 展示摘要 | 已接触、待复习或最近完成的目标摘要。 | 由学习模块计算；未来家长端需授权后读取，不把页面字段当事实来源。 |

### 记录原则

- 稳定关联 `textbookId`、`contentVersion`、`grade`、`unitId`、`knowledgePointId`、`taskId`；题目顺序或显示文字不能当 ID。
- 区分 `introduced`（见过）、`practiced`（练过）、`needs_review`（适合再复习）等学习经历。只有经明确设计的多次证据才可支持掌握判断，不能由“我认识了”一次自报或一次答对直接推断。
- MVP 只留恢复会话和展示必要摘要的最少数据。若记录作答结果，保存稳定任务引用、完成事实和是否使用提示等最低限度；是否保留逐次答案须另有评估理由与期限。
- 不默认保存儿童姓名、精确位置、原始口语录音、录音转写或与学习无关的行为轨迹。避免为了未来分析而添加埋点。
- 离线先写本地；格式变化显式提升 schema 并迁移，保留旧档案；重复的课程／任务事件按稳定 ID 去重。
- 时间戳用于恢复与复习安排，不用于公开排名或奖励资格的生产权威判断。
- 若未来增加家长端、云同步或语音，需先明确信息告知、监护人授权、查看／删除、访问控制和保留期限。

### 与现有 Alpha 记录的关系

Alpha 当前保存 `progress.completedWordIds`、`learningRecords`（包括 `wordId`、`courseId`、`grade`、`status`、`learnedAt`）和 `gameState`；“我认识了”只表示孩子自选标记，尚不是正式掌握评测。本设计不要求立即改变本地档案 v4。将来若新增任务／复习字段，先定义版本迁移与旧词 ID／教材 ID 映射，再单独评审实现。

## 评审问题

1. 每日环节时长与单词数量是否适合真实目标儿童；是否把 15 分钟理解为上限而非每日要求。
2. 首期学习内容是否采用真实教材 Unit 1，还是先用原创内容完成可用性试点。
3. 口语是否仅作为不录音的自愿练习；若未来要录音，需另开隐私与产品评审。
4. MVP 需要保存哪些最少任务结果，保存多久，以及家长端未来可读取哪些摘要。
