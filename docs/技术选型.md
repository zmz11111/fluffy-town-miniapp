# 技术选型说明

## 推荐首期方案

| 领域 | 选择 | 原因与边界 |
|---|---|---|
| 客户端 | 微信小程序原生框架 | 目标平台明确，直接使用页面、音频与生命周期能力，减少适配层。 |
| 语言 | Sprint 1 使用 JavaScript + JSDoc，后续评估 TypeScript | 基础版本无需构建链即可导入开发者工具；词条、学习记录与宠物结构已有注释定义，扩展时可迁移为 TypeScript 类型。 |
| 页面样式 | WXSS + 设计 token | 轻量、贴合小程序；组件需统一字号、颜色、触控面积和儿童可读性。 |
| 内容 | 版本化 JSON + 静态资源 | 便于审校、差异比较和离线加载；经 schema 校验后发布。 |
| 本地存储 | 小程序本地存储封装 | MVP 保存进度与偏好；封装迁移、校验和异常处理，避免业务直连 API。 |
| 云端（后续） | 微信云开发适配层 | 若团队/部署条件适合，可用云函数、云数据库和云存储；先核实成本、地域、权限和删除能力。 |
| 内容导入 | PDF 抽取工具 + 人工审校 | OCR/抽取只产候选，不自动发布；授权信息随内容保存。 |
| 版本管理 | Git + 文档/内容审阅 | 内容修改可追溯；媒体大文件按体积和授权确定 Git LFS/对象存储策略。 |

## 暂缓引入

暂不绑定大型 UI 框架、跨端引擎、第三方用户分析、语音评分服务或复杂服务端架构。只有当平台需求、团队技能或性能数据证明必要时再评估。

## 工程约定

- 内容 schema、客户端类型与云端映射共享稳定业务 ID，但避免把数据库文档格式泄漏给 UI。
- 环境配置拆分为示例与本地私有配置；密钥、AppID 私有信息和用户数据不得提交。
- 音频优先使用已授权的录音/配音素材；格式、码率和体积根据真机表现决定。
- 工具链版本和微信基础库版本在真实项目创建时记录；本设计阶段不假定具体版本号。

## 决策门

进入实现前确认：开发者主体与小程序类目、云开发环境与预算、教材版权/授权、目标机型范围、视觉资源生产方式及儿童隐私审查要求。若云端不适用，架构中的仓库接口可接入自有服务或继续本地运行。
